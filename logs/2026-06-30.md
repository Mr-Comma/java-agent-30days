## 本轮实现
- 为 `GET /api-docs/debug-schema` 的字段元数据新增 `retryable`。
- `retryable` 标识字段缺失/非法后是否适合自动重试目标节点：可自动降级的工具、调试提示和 Prompt 变量为 `true`，需要补输入或重新分析的状态、阶段、阻塞原因和 Prompt 预览为 `false`。
- 同步更新服务层精确断言、Controller JSON 断言和 README 契约测试，确保运行时 schema、文档示例和字段表一致。

## 今日观点
`policySeverity` 说明策略强度，`retryable` 进一步告诉编排层能不能自动再试一次。两者结合后，Agent 节点可以区分“应用 fallback 后可重试”和“必须补输入/重新分析”，避免无意义循环。追加的 `operatorMessage` 则把机器策略翻译成可展示的人类操作提示，让调试面板能直接告诉用户下一步该补输入、重新分析，还是继续使用降级结果。
