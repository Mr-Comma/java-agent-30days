# 2026-06-22 Java Agent 学习日志

## 今日主题
Day 15：继续推进 Java Agent API 文档助手的调试契约，让 `/api-docs/debug-schema` 更适合前端调试面板和 Agent 编排层做字段溯源。

## 本轮完成
- 为 `ApiDocDebugField` 增加 `source` 字段，标明每个 debug 字段来自 `ApiDocAnalyzerService` 的哪个确定性输出。
- `GET /api-docs/debug-schema` 现在会为 `workflowStatus`、`workflowStage`、`suggestedTool`、`blockingReason`、`debugHints`、`reviewPromptVariables`、`reviewPromptPreview` 返回稳定 source 元信息。
- 更新 README 示例和文档契约测试，避免接口返回与说明漂移。

## 本轮追加
- 为 `ApiDocDebugField` 增加 `exampleValue` 字段，让 debug schema 同时给出可渲染的最小 READY 示例。
- `GET /api-docs/debug-schema` 现在会为工作流状态、阶段、建议工具、调试提示、Prompt 变量和 Prompt 预览返回示例值；`blockingReason` 在 READY 示例下保持 `null`，避免误导调用方。
- 补充 Controller JSON 断言和 README 契约测试，确保字段示例不会和文档漂移。

## 本轮继续追加
- 将 debug schema 的单一 `exampleValue` 拆成 `readyExampleValue` 和 `needsInputExampleValue`，让前端/Agent 调试面板能同时渲染可审查路径和缺输入路径。
- 为 `blockingReason`、`reviewPromptVariables`、`reviewPromptPreview` 补齐 NEEDS_INPUT 示例，继续保持缺输入场景不编造接口。
- 更新 Controller JSON 断言、README 契约测试和 README 示例，保证双路径样例字段稳定。

## 本轮小闭环
- 为 `ApiDocDebugField` 增加 `displayOrder`，让 `/api-docs/debug-schema` 显式返回字段展示顺序。
- 当前字段按 10、20、30... 排序，前端调试面板和 Agent 编排层可以基于稳定元数据渲染，而不必依赖数组下标。
- 更新 Controller JSON 断言、README 契约测试和 README 示例，保证展示顺序字段和文档同步。

## 今日观点
调试 schema 不只要告诉调用方“字段是什么”，还要告诉调用方“字段从哪来”。source 元信息能帮助前端面板、Agent 节点和后续审计逻辑定位字段来源，而不需要解析 README 或猜测服务内部实现。
