# 2026-07-06 Java Agent 学习日志

## 今日主题
Day 24+：继续把 API 文档助手的 debug schema 从“Runbook 入口”推进到“可执行 Runbook 步骤”。

## 本轮实现
- 为 `GET /api-docs/debug-schema` 的字段元数据新增 `runbookStep`。
- 将已有 `escalationRunbook` key 拆成一句稳定、可展示、可交给 Agent/调试面板执行的中文下一步：例如校验 `paths`、确认 `REVIEW_READY`、工具 fallback、收集阻塞输入、补写默认调试提示、补齐 Prompt 变量、收集非编造 Prompt 输入。
- 同步更新 `ApiDocDebugField`、`ApiDocDebugSchemaService`、Controller JSON 断言、README JSON 示例和完整字段表，保持 runtime contract 与文档一致。
- 本轮仍为 metadata-only，不改变 `/api-docs/analyze` 的业务行为，也不创建任何自动任务。

## 验证
- Baseline：变更前 `mvn -q -Dtest=ApiDocDebugSchemaServiceTest test` 通过。
- RED：先在测试里断言 `ApiDocDebugField::runbookStep`，确认旧 record 尚无 accessor 时编译失败。
- Targeted：`mvn -q -Dtest=ApiDocDebugSchemaServiceTest,ApiDocControllerTest,ReadmeApiDocExampleTest test` 通过。
- Full：`mvn test` 通过，20 tests, 0 failures, 0 errors。

## 学习点
`escalationRunbook` 更像“处理手册入口”，而 `runbookStep` 是“当前字段的下一步动作”。把两者拆开后，UI 可以展示人能读懂的步骤，Agent 编排层仍能保留稳定 key，不需要从中文长提示中再解析动作。
