## 今日观点
`nodeInputPath` 和 `handoffPayloadKey` 解决节点“读哪里、用什么键交接”，`requiredForNode` 则补上执行安全边界：哪些字段必须有，哪些字段允许为空。这个小元数据能帮助后续 Agent 编排层在执行前做轻量校验。

`fallbackValue` 是工作流鲁棒性的下一块小拼图：当节点拿不到期望字段时，优先降级到输入校验链路，而不是继续风险审查或编造接口。

## 本轮继续推进
- 为 `GET /api-docs/debug-schema` 的字段元数据新增 `validationRule`。
- `validationRule` 描述工作流节点应用 `fallbackValue` 前的最小输入校验规则，例如状态/阶段/工具必须落在确定枚举值内，结构化 Prompt 变量必须包含固定键，Prompt 预览必须非空。
- 同步更新服务层、Controller JSON、README 契约测试和 README 字段表，保持运行时 schema 与文档一致。
