## 今日主题
Day 22：继续把 API 文档助手的 debug schema 从“失败升级提示”推进到“多字段升级排序”。

## 本轮实现
- 为 `GET /api-docs/debug-schema` 的字段元数据新增 `escalationPriority`。
- `escalationPriority` 用数字给多个升级候选排序：输入状态/阶段优先级最高，阻塞原因和 Prompt 预览次之，可 fallback 字段统一放到低优先级。
- 同步补齐服务层精确断言、Controller JSON 断言、README JSON 示例和完整字段表，保持运行时 schema 与文档契约一致。
- 本轮保持 metadata-only，不改变 `/api-docs/analyze` 的业务行为。

## 今日观点
`failureEscalation` 解决“交给谁”，`failureEscalationMessage` 解决“展示什么”，`escalationPriority` 解决“多个问题先处理哪个”。把排序也放进 schema 后，调试面板或 Agent 编排层可以在不硬编码字段名的情况下稳定排序升级候选。
